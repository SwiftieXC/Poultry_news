# V1 日报业务表达

文中 `.data/` 路径指本地私有材料，不随仓库发布。

## 当前交付：部门内部日报

每个日期只生成一份日报，所有国家的内容放在同一连续列表内，正文和快讯连续编号，不按国家或业务类别分栏。国家、产品与政策范围仍保留在具体条目中；不同日期不会合并成一份伪装为当日日报的文件。

中文重量使用吨／万吨。`site/format.ts` 对明确的阿拉伯数字千吨数量精确换算：低于 1 万吨时用吨，否则用万吨；数量区间两端使用同一单位。使用十进制字符串移位，不经浮点舍入；原文、数据库原始值、URL 和代码片段保留，无法可靠解析的写法不猜测。生成提示词也按此单位要求写作，不在日报中解释换算过程。

使用者已确认先做“生成日报”，审阅确认后再推进其他步骤。当前入口生成本地独立 HTML 与 Markdown，读者无需启动网站；自动采集、持续 worker、定时文件导出、消息送达与公开部署尚未启用。本入口只编排已完成分析的资料，不负责采集或调用模型分析新资料。

实现位于 `modules/department-daily/`，作为本地命令使用，不注册到 API 或 worker。复用 `composeDaily` 编排，再经 `publication/loadReport` 读取，按当前撤回状态导出；没有修改框架、数据库定义、迁移、评分阈值或默认模型。

### 生成命令

需要 Node.js 和已有已迁移的 PostgreSQL 数据库，数据库中有对应窗口完成筛选的资料或已有日报。`DATABASE_URL` 必须显式配置；本命令不会建库、迁移、修改 `.env` 或打开安全阀。

```powershell
Set-Location D:\dev\projects\poultry_news
# DATABASE_URL 由本机已有配置提供，不在命令或文档中填写真实密码。
npm run daily:generate -- --date 2026-10-08
```

默认输出 `.data/dailies/2026-10-08/daily.html` 与 `daily.md`。可用 `--out DIRECTORY` 指定新目录；默认归档目录受 `.gitignore` 保护，自定义目录也应保持私有。隔离 `_test`／`_ci` 数据库必须添加 `--sample`，文件会标明“历史回放样刊 · 待审阅”。

- 指定日期尚未到 08:00 截止时拒绝生成，避免把未完成窗口当完整日报。
- 已有数据库日报直接复用，不自动重写历史版本；相同导出目录存在时拒绝覆盖，重新导出需指定新目录。
- 没有完成筛选的资料时失败，不伪造“市场平静”的空刊。已筛选但没有入选内容时，可生成有明确范围说明的空刊。
- 撤回条目只显示撤回占位，不带旧标题、摘要或链接；正文只保留摘要和证据链接，不导出原文全文或编辑评分。
- 已生成的文件是静态快照，后续撤回不会自动修改旧文件；重新经读取层导出新版本可反映最新撤回状态。
- 使用既有中文排版函数；按确定性标签将已有“业务含义／今日值得跟进”分段，不生成额外判断，也不补造原摘要缺少的内容。

## 业务表达与编排

日报仍由上游规则编排，不新加模型调用、不改报告数据库。日报窗口为北京时间前一天 08:00 到当天 08:00；每日 08:00、周一 10:00、每月 1 日 10:30 出刊。

入选条目 summaryZh 最多3句、180字：第一句是有出处的核心变化与适用范围；有直接影响时用“业务含义：”说明，推断标“可能／若”；有明确对象时用“今日值得跟进：”给具体核实或业务研究动作。跟进落到已披露项目、时间节点、产品或数据比较，不凑“核对范围和口径”的通用尾句。不追加“未披露成交”“仍以企业所述为准”等自证；必要产品和政策条件融入事实句。editorialJudgment只说明业务阅读价值，UI标签为“业务含义”，隐藏评分。

示例为合成验收材料，不是实际新闻：

> 日本主管机构公告新增某中国工厂的熟制禽肉注册，适用于公告列明的工厂和熟制产品。业务含义：该工厂对日可供应范围扩大。今日值得跟进：将公告工厂编号、产品和生效日与现有出口证书逐项比对。

原生日报会展示每条摘要，因此跟进建议在条目内可读；尚无跨条目独立“今日跟进清单”，也没有负责人、期限、状态或通知。首页卡片会折叠摘要，完整文字可在条目与日报中读取。空刊只说明采集范围内没有入选内容，不声称市场平静或没有风险。

日本优先准入、检疫、具体采购、中国同行和进口数据；MENA 优先有证据的买家动作与政策准入，其次贸易增长、招标、竞争供给、价格和渠道。贸易替代是待核实的推断，必须核对中国准入与产品规格；疫情公告和进口禁令分别表述。
